# LG Smart Cottage ROI 한국 v9.1 통합 사양 (SPEC)

이 문서가 v9.1의 유일한 사양이다. 이전 대화 지시, 이전 프롬프트, 기존 코드 동작과 다르면 이 문서를 따른다. 이 문서에 없는 기존 기능은 실행하지 말고 "삭제 후보" 목록으로 보고한다.

---

## 0. 클린 실행 원칙

1. 시작 전에 `git add -A && git commit -m "pre-v9.1 snapshot"`을 실행한다.
2. `korea/output/`, `korea/report/`의 기존 파일을 모두 `archive/<날짜>_pre_v9_1/`로 옮겨 두 폴더를 비운 뒤 시작한다. 이전 산출물(results_summary.md, validation.md, report_data.json, CSV, HTML)을 입력이나 참고로 읽지 않는다. 단, v8 HTML은 14절 레이아웃 복구용으로만 읽는다.
3. `run_id = 실행시각(ISO) + git 짧은 해시 + config·입력 CSV의 SHA256 앞 8자리`를 만든다. 모든 산출물(md·csv·json·html) 첫 줄 또는 메타에 기록한다.
4. 코드에서 EV, DUO Max 증분(incremental), PPT 생성, Zero energy "당일 PV 충족", Critical Day 표 관련 함수·설정·테스트를 삭제한다. 삭제한 파일·함수 목록을 validation.md 0절에 남긴다.
5. 국가별 숫자 하드코딩 금지. 모든 입력은 `korea/config`에 `value·unit·source·status`로 둔다. status는 VERIFIED / UNVERIFIED / PLACEHOLDER / ASSUMPTION 중 하나다.
6. 보고서·요약·검증 문서의 모든 숫자·결론·판정 문장은 `report_data.json`에서 템플릿으로 생성한다. 수기 문장, 형용사형 평가("고효율", "극대화", "안정성 확인", "실증"), 근거 없는 수치·원인 서술은 금지한다.

## 4. KOSIS 수집 (engine/data/kosis_fetch.py)

### 4-1. 키와 요청 방식
- API 키는 환경변수 `KOSIS_API_KEY`에서 읽고 앞뒤 공백·탭을 제거한다. 어떤 파일·로그에도 키를 쓰지 않으며, URL에서는 `apiKey=***`로 가린다.
- 목록은 statisticsList(vwCd=MT_ZTITLE), 메타는 getMeta(type=ITM), 자료는 Param/statisticsParameterData(prdSe=F, 2024)로 받는다.
- 요일·성별 조합별로 나눠 호출한다. 호출 간 0.5초 대기, 오류 시 1회만 재시도한다.

### 4-2. 수집할 표 (모두 "30분간격 > 행동비율", 2024)

| 약칭 | 표 이름 | 알려진 TBL_ID | 용도 |
|---|---|---|---|
| T1 | 일-평일 행동비율(15세 이상 취업자) | DT_2019_160_1TM2031XX | 취업자 평일 일 |
| T2 | 일 관련 이동-행동비율(15세 이상 취업자) | DT_2019_184_1TM2123XX | 취업자 출퇴근 |
| T3 | 문화 및 여가활동-취업여부별 행동비율(15세 이상) | DT_2019_181_1TM2106XX | 취업자 여가·미디어 |
| T4 | 교제 및 참여활동-취업여부별 행동비율(15세 이상) | DT_2019_176_1TM2101XX | 취업자 교제 |
| P | 개인유지-행동비율(10세 이상) | 목록에서 찾기 | 수면·식사·개인위생 |
| H | 가정관리-행동비율(19세 이상) | 목록에서 찾기 | 식사준비·설거지·세탁·청소 |
| CR | 가족 및 가구원 돌보기-행동비율(19세 이상) | 목록에서 찾기 | 돌보기 |
| V | 자원봉사 및 무급연수-행동비율(10세 이상) | 목록에서 찾기 | 자원봉사 |
| MV | 이동-행동 비율(10세 이상) | 목록에서 찾기 | 이동 전체·세부 |
| M | 시간대별 행동비율(10세 이상) | DT_2019_191_1TM2129XX | 7구간 묶음, 점검용·주말 일 수준용 |

- 목록에서 찾을 표는 parentListId=B_9_001_004_001_001에서 TBL_NM으로 찾는다. 못 찾으면 상위 목록을 한 단계씩 탐색하고, 그래도 없으면 중단한다.
- 차원 선택(이름 기준): 요일 = 평일/토요일/일요일(차원이 있을 때), 성별 = 남자/여자, 취업여부 = 취업자, 행동 = ALL, 시간대 = ALL.

### 4-3. 정리 규칙
- 원본 JSON은 `korea/source/kosis/raw/`에 저장한다.
- 정리 CSV는 `korea/source/kosis/<약칭>_2024.csv`로 저장한다. 열: table, day_code, day_name, sex_code, sex_name, emp_name, act_code, act_name, act_level, slot_code, slot_name, slot_start, value.
- act_level은 코드 길이로 판별한다(1자리 = 대, 2자리 = 중, 3자리 = 소).
- 시간대는 slot_name의 "HH:MM~HH:MM"를 파싱해 30분 칸만 남긴다. M은 7구간을 그대로 둔다.
- 빈칸 처리: 행동 × 요일 × 성별마다 48칸을 채우고, 응답에 없는 칸은 0으로 넣는다. 표·행동별로 채운 칸 수를 기록한다.

### 4-4. 점검 (validation.md 1절, 실패 시 중단)
- 표별로 TBL_ID, 선택 코드, 원 행 수, 0으로 채운 칸 수, 시간대 칸 수, 요일 차원 유무를 표로 적는다.
- T1~T4, P, H, MV 중 하나라도 30분 48칸이 아니면 중단한다.
- 정합성 점검: P·H·MV 30분 값을 M의 7구간으로 다시 묶어 M과 비교한다(구간별 차이 %p 최대값 기록). 이는 판정 없이 기록만 한다.
- SOURCE.md에는 표 이름, TBL_ID, 키를 뺀 URL, 수집 일시, status=VERIFIED(API 원자료)를 적는다.

## 5. 취업 성인 행동비율 구성 (요일유형 d, 성별 g, 30분 칸 t)

1. **일 W**
   - 평일 = T1 대분류 "일".
   - 토·일 = M의 해당 요일 구간값(10세 이상 일) × T1 모양(구간 내 T1(t)/구간평균 T1). ASSUMPTION으로 표기한다.
2. **일 관련 이동 C** = T2 합계. 요일 차원이 없으면 평일만 T2를 쓰고 주말은 0이다.
3. **여가 L**(문화 및 여가 대분류) = T3. **미디어 이용 L_media** = T3의 미디어 이용 중분류(없으면 실시간 방송 + 동영상 시청 소분류 합).
4. **교제 S**(교제 및 참여 대분류) = T4.
5. **나머지 R** = 1 − W − C − L − S.
   - R을 개인유지(P), 가정관리(H), 돌보기(CR), 자원봉사(V), 기타 이동에 각 표의 비율대로 배분한다.
   - 기타 이동 = MV 전체 − 일 관련 이동 − 학습 관련 이동.
   - 학습(3)과 학습 관련 이동은 0으로 두고 제외한다.
   - 하위 항목(수면 111, 식사하기, 개인위생, 식사준비, 설거지·식후정리, 세탁하기, 세탁물 건조, 청소, 정리)은 상위 배분 배율을 그대로 적용한다.
6. 음수가 생기면 0으로 자르고 칸별 합이 100%가 되도록 재정규화한다. 자른 칸 수를 기록한다.
7. **상태 확률**
   - 수면 = 수면(111)
   - 외출 = W + C + 기타 이동 + 자원봉사 + κ × (S + L − L_media). κ = 0.5(ASSUMPTION), 민감도 0.3 / 0.7.
   - 재택·활동 = 1 − 외출 − 수면
8. 1인 가구는 남녀 평균, 2인은 남1·여1, 3인은 남1·여1·평균1로 구성한다.
9. 보고서 표기 문구: "KOSIS 2024 생활시간조사의 취업자 시간대별 행동비율(평일 일·출퇴근·여가·교제)과 10세 이상(가정관리는 19세 이상) 행동비율을 결합한 통계 기반 확률 시뮬레이션(실측 아님). 주말 근무 비율은 10세 이상 값을 사용."

## 6. 부하 모델 (engine/occupancy_tus.py)

- **해상도**: 30분 → 10분은 구간 내 일정값(합 보존)으로 둔다. 시뮬레이션 후 15분으로 재집계한다.
- **하루 경로**: 개인별로 3상태(외출 / 재택·활동 / 재택·수면) 시간 비균질 마르코프 체인을 쓴다.
  - 전이행렬 T = (1−λ)·T_min + λ·(1ᵀπ(t+1)). T_min은 π(t)T = π(t+1)을 만족하면서 상태 유지가 최대인 최소전환 해다.
  - λ는 평일 외출 에피소드 수 평균이 1~2회가 되도록 보정한다.
- **활동 확률**: P(행동 a | 재택·활동, t) = 행동비율_a(t) / P(재택·활동, t).
- **가전 매핑**

| 행동 | 가전·부하 |
|---|---|
| 식사준비 | 인덕션·광파오븐 |
| 설거지·식후정리 | 식기세척기 |
| 세탁하기 | 세탁기·워시타워 |
| 세탁물 건조 | 건조(해당 모델) |
| 실시간 방송·동영상 시청 | TV·플러그 |
| 청소 | 플러그 이벤트 |
| 개인위생 | 급탕 시점 |

- **켜짐 확률** = 활동 확률 × 보정계수. 보정계수는 가전별 연간 kWh(기존 config, 인원 연동)와 ±0.5% 이내가 되도록 이분법으로 맞춘다. 정격전력·1회 사용시간은 appliance_events_table을 쓴다.
- **가구 단위 이벤트**: 취사·세탁·식기세척은 재택·활동 인원 중 한 명이라도 해당 활동이면 발생한다.
- **조명**: 재택·활동 인원 × GHI 임계치 이하일 때 점등(CREST 방식). 연간 조명 kWh(면적 연동)에 맞춰 보정한다.
- **급탕**: 75L/인·재실일. 개인위생 확률에 비례해 시점을 배분한다.
- **난방 설정온도**(ASSUMPTION, 보고서 표기): 재택·활동 20°C / 수면 18°C / 외출 16°C / 비재실일 10°C. 5R1C에 15분 단위로 적용한다.
- **시드**: 기본 42, 민감도 42~51.

## 7. 통계 재현 확인 (validation.md 2절)

- 재실 달력과 무관하게 요일유형별 2,000 인-일 이상 별도 시뮬레이션으로 계산한다.
- 5절에서 구성한 목표 곡선과 비교한다. 비교 곡선: 수면, 외출, 식사준비, 실시간 방송 시청.
- 시간대별 MAE(%p)를 구하고 기준 ≤ 2%p로 PASS/FAIL을 판정한다.
- FAIL이면 원인 후보(클리핑, 30→10분 변환, 성별 가중, 공휴일 처리, λ)별 MAE 변화 표를 남기고 FAIL을 그대로 둔다.
- 가전별 연간 kWh 보정 오차도 기록한다.

## 9. 현금흐름·회수기간

- 100년, 할인 없음, 요금·연료 단가는 현재값 고정이다.
- 각 해의 현금흐름 = 연간 이득(기준안 총에너지비용 − 대안 총에너지비용, PV 감쇄 반영) − 해당 연도 교체비.
- 회수기간 = 누적 현금흐름이 마지막으로 0을 넘은 뒤 100년 차까지 0 이상을 유지하는 시점. 연내 선형보간, 소수 1자리.
- 표기 규칙
  - 100년 안에 회수하지 못하면 "불가능".
  - 연간 이득 ≤ 0이면 "불가능(연간 이득 없음)".
  - JSON에는 null과 사유 코드만 넣는다. 999 같은 내부값은 출력 금지.
- 25년 누적 순현금흐름도 함께 출력한다.

## 10. 목표별 사이징

공통: 15분 디스패치, 월 합산 상계, 정상상태(연초 이월·SoC = 전년 말 값이 될 때까지 반복).

### 10-1. Near zero
- PV 0.5kW 단위 × ESS 0~4모듈 전체를 탐색한다.
- 회수기간 ≤ 3년 조합이 있으면, 그중 연간 변동요금 절감률이 가장 큰 조합을 고른다(동률이면 회수기간이 짧은 것).
- 없으면 최단 회수 조합을 고르고, "3년 달성 필요 순CAPEX = 3 × 연간 이득"과 필요 감액률을 함께 제시한다.
- 모든 결과에 연간 변동요금 절감률(%)을 표시한다. PV 단독 참고 열은 만들지 않는다.

### 10-2. Zero bill
- 연간 변동요금 0원(기본요금·세금 별도). ESS 최소 1모듈.

### 10-3. Zero energy
- ESS 보완 최소비용 조합만 계산한다. 외부 전력 수전은 0이다.
- ESS 사용 가능 용량 = 공칭 kWh × SOH 0.70 × SoC 창 × √RTE.
- 제약: ESS 사용 가능 용량 ≥ 해당 시나리오의 연중 최대 일부하. 이를 만족하는 최소 모듈 수부터 시작한다.
- 각 ESS 모듈 수(시작값 ~ +8모듈)마다 PV를 0.5kW 단위로 올리며 LOL = 0이 되는 최소 PV를 찾는다. PV 출력에는 수명 말기 계수 0.995^(25−1)을 적용한다.
- 그중 초기 순CAPEX(Central) 최소 조합을 고른다.
- 본문 사이징은 시드 42~51 10개 부하 모두에서 LOL = 0인 조합이다(시나리오별 70건). 시드별 단독 사이징 범위는 부록에 둔다.
- 진단: 100% 기준 시스템을 다른 이용률에 적용했을 때 케이스별 LOL·부족량·발생일·전날 재실 여부·당일 난방 kWh를 표로 출력한다. 판정은 붙이지 않는다.
- 가스 케이스는 프로판을 계속 사용한다(전력 기준 Zero energy로 표기).
- 부록 저장 항목: 탐색 곡선, 365일 일부하 vs 일 PV vs ESS 사용 가능 용량, 최저 일사 구간 7일의 15분 SoC.
